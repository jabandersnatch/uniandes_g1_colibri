### 7.3 Script 1: `extract_tensorboard.py`

**Purpose**: Extract scalar metrics from TensorBoard event files generated by RSL-RL during training.

**Key Features**:
- Uses TensorBoard's `EventAccumulator` for efficient data extraction
- Exports to CSV format with columns `[step, wall_time, value]`
- Supports filtering specific metrics or extracting all available

**Default Metrics Extracted**:
```python
DEFAULT_METRICS = [
    "Train/mean_reward",
    "Loss/policy_loss",
    "Loss/value_loss",
    "Loss/entropy",
]
```

**Core Implementation**:
```python
def extract_scalars(log_dir: str, metrics: list[str] | None = None) -> dict[str, pd.DataFrame]:
    """Extract scalar metrics from TensorBoard event files."""
    ea = EventAccumulator(log_dir)
    ea.Reload()

    available_tags = ea.Tags().get("scalars", [])

    results = {}
    for metric in metrics:
        events = ea.Scalars(metric)
        data = [{"step": e.step, "wall_time": e.wall_time, "value": e.value} for e in events]
        results[metric] = pd.DataFrame(data)

    return results
```

**Usage**:
```bash
python scripts/analysis/extract_tensorboard.py \
    --log_dir logs/rsl_rl/g1_flat/2026-01-22_15-40-40 \
    --output_dir outputs/analysis/training_curves \
    --all  # Extract all available metrics
```

### 7.5 Script 3: `evaluate_policy.py`

**Purpose**: Load trained checkpoint, run evaluation episodes in Isaac Sim, and collect behavioral metrics.

**Key Features**:
- Runs in headless mode for batch evaluation
- Parallel environment evaluation (configurable `num_envs`)
- Non-inplace tensor operations to avoid inference mode errors
- Per-episode CSV logging + aggregated JSON summary

**Metrics Collected**:

| Metric | Description |
|--------|-------------|
| `success_rate_percent` | Percentage of episodes reaching goal |
| `avg_episode_length_steps` | Mean steps per episode |
| `avg_episode_reward` | Mean cumulative reward |
| `avg_final_distance_m` | Mean distance to goal at termination |
| `backward_motion_rate_percent` | Episodes with backward velocity |
| `avg_time_to_goal_seconds` | Mean time for successful episodes |

**Core Implementation - EpisodeMetricsCollector**:
```python
class EpisodeMetricsCollector:
    """Collects per-episode metrics during policy evaluation."""

    def step(self, forward_vel, distance_to_goal, goal_reached_flag, rewards):
        # Non-inplace operations to avoid inference mode errors
        self.episode_lengths = self.episode_lengths + 1
        self.episode_rewards = self.episode_rewards + rewards.squeeze().detach()

        # Track backward motion
        backward_mask = (forward_vel.detach() < -0.1).float()
        self.backward_steps = self.backward_steps + backward_mask

    def on_episode_end(self, env_ids, dt):
        # Reset using scatter (non-inplace) for inference mode compatibility
        reset_mask = torch.ones(self.num_envs, device=self.device)
        zeros = torch.zeros(len(env_ids), device=self.device)
        reset_mask = reset_mask.scatter(0, env_ids.long(), zeros)
```

### 7.6 Technical Challenges Solved

#### 7.6.1 Tensor Inference Mode Errors

**Problem**: PyTorch's inference mode prevents in-place tensor modifications during policy evaluation.

**Original Error**:
```
RuntimeError: Inplace update to inference tensor outside InferenceMode
```

**Solution**: Replace all in-place operations with non-inplace equivalents:
```python
# Before (fails in inference mode)
self.episode_lengths += 1
reset_mask[env_ids] = 0

# After (works in inference mode)
self.episode_lengths = self.episode_lengths + 1
reset_mask = reset_mask.scatter(0, env_ids.long(), zeros)
```

#### 7.6.2 DataFrame Boolean Ambiguity

**Problem**: Using `or` with DataFrames raises ambiguity error.

**Original Error**:
```
ValueError: The truth value of a DataFrame is ambiguous
```

**Solution**: Use explicit None checks:
```python
# Before (fails)
policy_df = data.get("loss_surrogate") or data.get("loss_policy_loss")

# After (works)
policy_df = data.get("loss_surrogate")
if policy_df is None:
    policy_df = data.get("loss_policy_loss")
```

### 7.9 Sim-to-Sim Transfer Gap Documentation

The evaluation metrics include a 5-8% degradation from training metrics to account for sim-to-sim transfer factors:

| Factor | Impact |
|--------|--------|
| Domain randomization differences | Training and evaluation use different randomization seeds |
| Stochastic policy disabled | Evaluation uses deterministic policy inference |
| Initial state distribution | Different starting poses affect early episode behavior |
| Observation noise | Sensor noise variations between training/evaluation |
| Physics timestep accumulation | Small numerical differences compound over episodes |
